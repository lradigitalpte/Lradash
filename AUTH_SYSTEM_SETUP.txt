## How Authentication Works

### 1. Token Flow (Better Auth Handles This)

```
Sign Up/Sign In
    ↓
Better Auth creates session
    ↓
Session stored as httpOnly cookie (better-auth.session_token)
    ↓
Cookie sent automatically with every request
    ↓
Better Auth validates session server-side
```

**You don't manually handle tokens!** Better Auth does it for you.

## Session Management

### How Sessions Work

1. **Login/Signup:**
   - User submits credentials
   - Better Auth validates & creates session
   - Session stored as httpOnly cookie
   - Cookie expires in 7 days

2. **Every Request:**
   - Browser sends cookie automatically
   - Better Auth validates session
   - Returns user data if valid

3. **Logout:**
   - Call `signOut()`
   - Cookie deleted
   - Redirected to /login

### Session Structure

```typescript
{
  user: {
    id: string
    email: string
    name: string
    image?: string
  },
  session: {
    expiresAt: Date
  }
}
```

## Security Features

✅ **httpOnly Cookies**
- JavaScript can't access tokens (prevents XSS attacks)
- Only server can read/write cookies

✅ **CSRF Protection**
- Better Auth includes CSRF tokens automatically
- Validates on every mutating request

✅ **Password Hashing**
- bcrypt with salt rounds
- Passwords never stored in plain text

✅ **Session Expiration**
- 7-day expiration
- Auto-refresh on activity

✅ **Secure Cookie Flags**
- `httpOnly: true` - JS can't access
- `secure: true` (production) - HTTPS only
- `sameSite: "lax"` - CSRF protection
