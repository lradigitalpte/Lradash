1.1 NOTIFICATION SYSTEM
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
Status: ❌ NOT IMPLEMENTED
Priority: CRITICAL
Effort: 3-4 weeks

Features Needed:
□ Notification database model
  - id, userId, type, entityType, entityId, message, read, createdAt
  - Types: task_assigned, task_mentioned, task_commented, task_due_soon,
           task_overdue, board_invited, project_updated, etc.

□ Notification API endpoints
  - GET /api/notifications (list user notifications)
  - GET /api/notifications/unread-count
  - PUT /api/notifications/[id]/read (mark as read)
  - PUT /api/notifications/mark-all-read
  - DELETE /api/notifications/[id]

□ Real-time notification delivery
  - WebSocket or Server-Sent Events (SSE)
  - Push notifications (browser/desktop)
  - Email notifications (optional)

□ Notification UI components
  - Notification bell icon with badge count
  - Notification dropdown/panel
  - Notification center page
  - Notification preferences/settings

□ Notification triggers
  - When task assigned to user
  - When user mentioned (@username)
  - When task commented on
  - When task due date approaching
  - When task overdue
  - When board/project updated
  - When user invited to board

Database Schema:
  Notification {
    _id: ObjectId
    userId: ObjectId (ref: User)
    type: String (enum)
    entityType: String (Task, Board, Project, Comment)
    entityId: ObjectId
    message: String
    read: Boolean (default: false)
    metadata: Object (optional extra data)
    createdAt: Date
  }

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Priority: CRITICAL
Effort: 2-3 weeks

Features Needed:
□ Comment database model
  - id, taskId, userId, content, parentId (for replies), createdAt, updatedAt

□ Comment API endpoints
  - POST /api/tasks/[id]/comments (create comment)
  - GET /api/tasks/[id]/comments (list comments)
  - PUT /api/comments/[id] (edit comment)
  - DELETE /api/comments/[id] (delete comment)

  Comment {
    _id: ObjectId
    taskId: ObjectId (ref: Task)

Options:
1. Socket.io (recommended for MVP)
   - Easy to implement
   - Good documentation
   - Room/channel support

2. Pusher (recommended for production)
   - Managed service
   - Scalable
   - Built-in presence
   - Cost: ~$50/month

3. Server-Sent Events (SSE)
   - Simpler than WebSocket
   - One-way only (server → client)
   - Good for notifications

4. Native WebSocket
   - Full control
   - More complex
   - Need to handle reconnection

Recommendation: Start with Socket.io, migrate to Pusher for production.
